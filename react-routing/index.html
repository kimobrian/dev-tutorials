JSX & The Virtual DOM

Before writing a component, understand what React actually is and what JSX compiles into.

JSXVirtual DOMReact.createElementReconciliation
Mental Model

React maintains a lightweight JS copy of the DOM. When state changes it diffs old vs new virtual trees and only updates the actual DOM nodes that changed — minimising expensive repaints.

What JSX compiles to

You write (JSX)
tsx
<h1 className="title">
  Hello, {name}!
</h1>
Compiled to JS

React.createElement(
  'h1',
  { className: 'title' },
  `Hello, ${name}!`
)

Use className (not class) and htmlFor (not for) — they map to DOM properties, not HTML attributes.

Published
tsx
<span className={`badge ${status}`}>Published</span>
// NOT: class="badge green"

Inline styles use a JS object with camelCase property names — not a CSS string.

Blog Post Title

</h1>

JSX must have a single root. Use <>…</> (Fragment) to wrap siblings — it renders no extra DOM node.

Chapter 03 React Fundamentals

State & useState

State is what makes React UIs dynamic. When state changes, React re-renders the component. Understanding when and why renders happen is React's most important concept.

useStateReactive re-rendersAsync updatesImmutabilityLifting state up
Mental Model

React is a painter who only repaints when you ring a bell. The useState setter is the bell. Call it → React re-runs your function → the screen updates. Plain variables never ring the bell.

useState — the blog post like button

src/components/LikeButton.tsxtsx
import { useState } from 'react'

function LikeButton({ initialLikes = 0 }) {
  const [likes, setLikes] = useState(initialLikes)
  const [liked, setLiked] = useState(false)

  function toggle() {
    const nowLiked = !liked
    setLiked(nowLiked)
    setLikes(prev => prev + (nowLiked ? 1 : -1))  // functional update
  }

  return (
    <button onClick={toggle} className={liked ? 'liked' : ''}>
      {liked ? '❤️' : '🤍'} {likes} likes
    </button>
  )
}

function SearchBar({ onSearch }: { onSearch: (q: string) => void }) {
  const [query, setQuery] = useState('')

    setQuery(e.target.value)

      onKeyDown={handleKeyDown} placeholder="Search posts… (Esc to clear)" />
  )
}

The controlled component pattern — React owns the input value. This enables real-time validation, conditional submission, and instant feedback.

New post form — full controlled implementation

src/components/NewPostForm.tsxtsx
function NewPostForm({ onSubmit }: { onSubmit: (d: PostData) => Promise<void> }) {
  const [form,       setForm]       = useState({ title: '', body: '', published: false })
  const [errors,     setErrors]     = useState<Record<string,string>>({})
  const [submitting, setSubmitting] = useState(false)

  function validate() {
    const e: Record<string,string> = {}
    if (!form.title.trim())      e.title = 'Title is required'
    if (form.body.length < 20)  e.body  = 'Body must be at least 20 chars'
    setErrors(e); return Object.keys(e).length === 0
  }
  async function handleSubmit(e: FormEvent) {
    e.preventDefault()
    if (!validate()) return
    setSubmitting(true)
    await onSubmit(form)
    setSubmitting(false)
  }
}

Chapter 08 React Fundamentals

useRef & The DOM

useRef gives you a mutable container that survives re-renders without causing them — and direct DOM node access when you need it.

useRefDOM accessMutable valuesFocus management
useRef — Two Use Cases
DOM access
Attach to a JSX element with ref={myRef}. myRef.current = the actual DOM node. Focus, scroll, measure.
Mutable value
Store any value that must persist across renders without triggering re-renders. Timer IDs, previous values, abort controllers.
src/components/CommentForm.tsx — useRef in actiontsx
export function CommentForm({ postId }: { postId: number }) {
  const [body, setBody] = useState('')
  const textareaRef = useRef<HTMLTextAreaElement>(null)
  const charCountRef = useRef(0)   // doesn't need to trigger re-renders

  useEffect(() => {
    textareaRef.current?.focus()  // auto-focus on mount
  }, [])

  function handleChange(e: ChangeEvent<HTMLTextAreaElement>) {
    setBody(e.target.value)
    charCountRef.current = e.target.value.length  // no re-render!
  }
  return <textarea ref={textareaRef} value={body} onChange={handleChange} />
}

useReducer & Complex State

When useState spawns 5+ related variables with complex update logic, useReducer consolidates them into a predictable state machine.

useReducerReducer patternAction typesDispatchState machine

Post form reducer — the blog's create flow

src/reducers/postForm.tstsx
type State = { title: string; body: string; status: 'idle'|'submitting'|'success'|'error'; errorMsg: string|null }
type Action =
  | { type: 'SET_FIELD'; field: 'title'|'body'; value: string }
  | { type: 'SUBMIT_START' } | { type: 'SUBMIT_OK' }
  | { type: 'SUBMIT_FAIL'; error: string } | { type: 'RESET' }

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'SET_FIELD':    return { ...state, [action.field]: action.value }
    case 'SUBMIT_START': return { ...state, status: 'submitting', errorMsg: null }
    case 'SUBMIT_OK':    return { title:'', body:'', status:'success', errorMsg:null }
    case 'SUBMIT_FAIL':  return { ...state, status:'error', errorMsg: action.error }
    case 'RESET':        return { title:'', body:'', status:'idle', errorMsg:null }
    default:           return state
  }
}

Chapter 11 React Fundamentals

Custom Hooks

Custom hooks are the primary way to share stateful logic between components. They're ordinary functions that call React hooks — the most powerful abstraction layer React provides.

Custom hooksLogic reuseuse prefixComposing hooks

useFetch — used across every data-loading page

src/hooks/useFetch.tstsx
export function useFetch<T>(url: string) {
  const [data,    setData]    = useState<T|null>(null)
  const [loading, setLoading] = useState(true)
  const [error,   setError]   = useState<string|null>(null)
  const [tick,    setTick]    = useState(0)  // bump to refetch

  useEffect(() => {
    let cancelled = false; setLoading(true)
    api.get<T>(url)
      .then(r => { if(!cancelled) { setData(r.data); setError(null) } })
      .catch(e => { if(!cancelled) setError(e.message) })
      .finally(() => { if(!cancelled) setLoading(false) })
    return () => { cancelled = true }
  }, [url, tick])

  return { data, loading, error, refetch: () => setTick(t => t+1) }
}

tsx
function useDebounce<T>(value: T, delay = 300) {
  const [debouncedValue, setDebouncedValue] = useState(value)
  useEffect(() => {
    const id = setTimeout(() => setDebouncedValue(value), delay)
    return () => clearTimeout(id)
  }, [value, delay])
  return debouncedValue
}

Composing hooks — usePostSearch combines useDebounce + useFetch + useLocalStorage into one clean interface.

tsx
// A composed hook used in the blog's search page:
function usePostSearch() {
  const [q, setQ]       = useLocalStorage('last-search', '')
  const debouncedQ       = useDebounce(q, 300)
  const { data, loading } = useFetch(`/posts?q=${debouncedQ}`)
  return { query: q, setQuery: setQ, results: data, loading }
}
// Now in any component — zero boilerplate:
const { query, setQuery, results } = usePostSearch()

Chapter 12 React Router v7

Router Setup & Core Concepts

React Router v7 ships as a single react-router package (no more react-router-dom). It offers three modes: Framework (full SSR/Vite plugin, like Remix), Data (createBrowserRouter — what this tutorial covers), and Declarative (classic <Routes> for simple apps).

createBrowserRouterRouterProviderRoute objectsClient-side routing
Mental Model

The address bar is another piece of state. React Router reads it and renders the matching component. A <Link> updates URL state without a page reload.

src/main.tsxtsx
// react-router v7 — single package, no more react-router-dom
import { createBrowserRouter, RouterProvider } from 'react-router'

const router = createBrowserRouter([{
  path: '/', element: <Root />, errorElement: <GlobalError />,
  children: [
    { index: true,    element: <IndexPage />,   loader: indexLoader },
    { path: 'posts/:id',  element: <PostPage />,   loader: postLoader },
    { path: 'posts/new',  element: <NewPostPage />, loader: newPostLoader, action: newPostAction },
    { path: 'login',     element: <LoginPage />,    action: loginAction },
  ]
}])
Framework Mode

Full-stack SSR, file-based routing, streaming — like Remix. Uses the Vite plugin @react-router/dev. Best for new projects wanting server rendering.

Data Mode ← this tutorial

Client-side SPA with createBrowserRouter. Same loaders/actions API as Framework, no server required. Drop-in upgrade from v6.

Route Object Properties
path
URL pattern. :name = dynamic segment. * = wildcard catch-all.
index:true
Matches parent path exactly — the default child route.
loader
Async function runs before component renders. Returns data via useLoaderData().
action
Handles form POSTs submitted to this route via <Form method="post">.
errorElement
Renders when loader/action/component throws. Bubbles up if not set.

export async function indexLoader({ request }: LoaderFunctionArgs) {

}

When does a component re-render?

  1. Its own state changes — setState was called
  2. Its parent re-rendered — unless wrapped in React.memo
  3. Its context value changed — any consumer re-renders
  4. A prop reference changed — even if the value is the same (object/array/function)

Chapter 29 React 19

React 19 — New Hooks & Actions

React 19 shipped in December 2024 with a set of hooks that directly replace common boilerplate: form state management, pending indicators, and optimistic UI — all without a state machine or useEffect.

useActionStateuseFormStatususeOptimisticuse()async Transitions
Mental Model

React 19 calls form handler functions "Actions". Any async function passed to a form's action= prop or wrapped in useTransition is an Action. The new hooks track the lifecycle of Actions automatically.

useActionState — form state in one hook

Before React 19 you needed three useState calls for a form: isPending, error, and the result. useActionState collapses all of that.

src/routes/login.tsx — useActionStatetsx
import { useActionState } from 'react'

async function loginAction(prev: State, formData: FormData): Promise<State> {
  const email = String(formData.get('email'))
  const pass  = String(formData.get('password'))
  try {
    await login({ email, pass })
    return { status: 'success' }
  } catch {
    return { status: 'error', error: 'Invalid credentials' }
  }
}

function LoginPage() {
  const [state, formAction, isPending] = useActionState(loginAction, { status: 'idle' })
  return (
    <form action={formAction}>   {/* ← native form action */}
      <input name="email" type="email" />
      <input name="password" type="password" />
      {state.error && <p>{state.error}</p>}
      <button disabled={isPending}>{isPending ? 'Logging in…' : 'Login'}</button>
    </form>
  )
}

useFormStatus — pending state inside a form

useFormStatus must be called inside a component that is a child of a <form>. It automatically reads whether that form is submitting — no prop drilling.

src/components/SubmitButton.tsxtsx
import { useFormStatus } from 'react-dom'  // note: from react-dom

function SubmitButton({ label }: { label: string }) {
  const { pending } = useFormStatus()  // reads parent <form>'s pending state
  return <button disabled={pending}>{pending ? 'Saving…' : label}</button>
}
// Reusable anywhere inside any form — knows if the form is submitting:
<form action={formAction}>
  <input name="title" />
  <SubmitButton label="Save Post" />  {/* ← auto-disables while submitting */}
</form>
